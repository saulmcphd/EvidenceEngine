<Procedure>
1. **Design Detection**: Identify the study design to determine if you are using PICO (Interventional) or PECOS (Observational) logic.
2. **Contextual Mapping**: Read the Methods to define the Population, Exposure/Intervention, and Comparison groups.
3. **Target Trial Emulation**: For observational studies, identify if the researchers attempted to emulate a pragmatic trial (e.g., through adjustment/matching).
4. **Numerical Data Scrutiny**: Locate the Results/Tables and record the REPORTED per-arm numbers (Mean, SD, N, Events) for each outcome AT EACH TIME POINT. Do NOT compute an effect size yourself; if the study reports a between-group effect estimate, record it verbatim in the Effect_Estimate fields and set Value_Provenance to "reported". Where the per-arm cells are incomplete, capture whatever recovers the analysis (the C47 fallback: a reported per-arm SE / 95% CI / IQR that recovers a missing SD, OR a between-group effect estimate WITH its SE / 95% CI / exact P / test statistic, OR individual-participant data), and if a result is reported with NO usable measure of precision, set Meta_Analysable_As_Reported to "no". NEVER perform a statistical conversion yourself (no log-transform, no SD-from-CI) - capture the reported numbers verbatim; the pooling software converts downstream (Cochrane §5.7).
5. **Bias Audit (design-branched)**: First set "RoB_Tool" from the study design - **RoB 2** (5 domains) for TRULY randomized trials only, **ROBINS-I** (7 domains) for observational AND non-/quasi-/pseudo-randomized studies (allocation by alternation, date, or record number is quasi-randomisation, NOT a true RCT -> ROBINS-I). Then populate ONLY that tool's domain block and mark every field of the other tool "Not applicable". Cite an exact supporting quote for each domain you judge.
6. **Evidence Mapping**: For every judgment and every data block, cite the exact quote/locus from the PDF.
</Procedure>


<Rules>
1. Return ONLY a JSON object. No conversational filler or markdown blocks.
2. If data is missing, use "Not reported". NEVER fabricate data - including a funding source, a COI declaration, or an adverse event that the paper does not report.
3. Maintain original decimal precision for all numbers.
4. Maintain the format: "[Judgment]; [Supporting Evidence/Quote]" for all RoB fields.
5. Extract RAW per-arm values, not the study's own computed OR/RR/SMD, so the review can compute one consistent measure later - UNLESS only an effect estimate is reported, in which case use the C47 Effect_Estimate fields and record the REPORTED ratio and its reported CI/SE verbatim. Do NOT log-transform it yourself - tag Effect_Estimate_Family as 'ratio' and the pooling software applies the natural-log downstream (Cochrane §5.7: conversions are done by computer downstream, not by hand at extraction).
6. Tag every result value Value_Provenance as "reported" (read verbatim) or "calculated" (you derived it); if "calculated", keep the reported source value too and say how you derived it in Calculation_Note. Never overwrite a reported number with a derived one.
7. When several results exist for one outcome (different scales / subgroups / time points), extract them ALL as separate Outcomes entries; do NOT pick one - the human applies the protocol's pre-specified selection rule.
8. For EVERY non-RoB data block, provide its verbatim source sentence or exact table locus in "Source_Quotes" under the identical key. Use "Not reported" for any block that was absent from the text. This lets a human check each extracted value against the paper (hallucination guard).
9. Conflicts of interest are RECORDED, NOT SCORED. Never add funding/COI as a risk-of-bias domain and never raise a domain's judgment merely because a conflict exists (Cochrane §7.8.3: the bias tool is built on mechanistically defined domains). The Notable_Concern_COI judgement is separate; a hypothetical or undeclared-only possibility is NOT a notable concern (§7.8.6). COI may inform the "Selection of the reported result" domain ONLY when the study's pre-specified analysis plan is missing.
</Rules>
